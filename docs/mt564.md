# read_mt564

*mt564 v0.1.1 · [README](../README.md) · [Shared behaviour](usage.md)*

```sql
read_mt564(path [, level := 'MESSAGE', option := value, ...])
```

Reads SWIFT FIN MT564 (Corporate Action Notification) messages. Input files are batches of messages as
exported by SWIFT interfaces and corporate-action feeds: `{1:...}{2:...}{4:` blocks, each closed by `-}`,
with every message starting on a new line. No surrounding file structure is required.

`path` is a file, a directory, a glob, or a list of these. Inputs, remote storage, type detection, NULL
handling and parallelism are described in [usage.md](usage.md).

The examples on this page use [`examples/notifications.txt`](../examples/notifications.txt). See the
[sample data disclaimer](../README.md#sample-data-disclaimer).

## Message structure

An MT564 message is a tree of sequences. Some sequences occur once, others repeat:

```
MESSAGE                  one per {1:...}{2:...}{4: ... -} block
├── GENL                 general information: event type (CAEV), mandatory/voluntary (CAMV), status
│   └── LINK             linkages
├── USECU                underlying security (35B) and account
│   ├── FIA              financial instrument attributes, repeats (e.g. one per listing)
│   └── ACCTINFO         account information
├── INTSEC               intermediate securities
├── CADETL               corporate action details: key dates and indicators
├── CAOPTN               corporate action option, repeats (e.g. cash or shares)
│   ├── CASHMOVE         cash movement, repeats
│   └── SECMOVE          securities movement, repeats
│       └── FIA          attributes of the delivered security, repeats
└── ADDINFO              additional narrative text
```

Fields are tagged lines. A qualified field such as `:22F::CAEV//DVCA` has tag `22F`, qualifier `CAEV` and
value `DVCA`. An unqualified field such as `:23G:NEWM` has only a tag. Continuation lines without a tag are
joined to the preceding field with a newline.

## Choosing a grain with `level`

A single flat row per message cannot represent this structure without losing or inventing data:

- An option (`CAOPTN`) can have any number of cash movements and any number of securities movements. They
  are independent of each other, so joining them would pair movements that have no relationship.
- `FIA` occurs in two places with different meanings: under `USECU` it describes the notified security,
  under `SECMOVE` it describes the security being delivered.

The `level` option therefore selects which sequence produces the rows:

| `level` | One row per | Columns after the context columns |
|---|---|---|
| `MESSAGE` (default) | message | Counts `NUM_USECU_FIA`, `NUM_CAOPTN`, `NUM_CASHMOVE_TOTAL`, `NUM_SECMOVE_TOTAL`, `NUM_SECMOVE_FIA_TOTAL`, and `OTHER_FIELDS` |
| `USECU_FIA` | `FIA` under `USECU` | `USECU_FIA_SEQ` and the fields of that `FIA` |
| `CAOPTN` | option | `CAOPTN_SEQ`, the option's fields, `NUM_CASHMOVE`, `NUM_SECMOVE` |
| `CASHMOVE` | cash movement | `CAOPTN_SEQ`, the option's fields, `CASHMOVE_SEQ`, the movement's fields |
| `SECMOVE` | securities movement | `CAOPTN_SEQ`, the option's fields, `SECMOVE_SEQ`, the movement's fields, `NUM_SECMOVE_FIA` |
| `SECMOVE_FIA` | `FIA` under `SECMOVE` | Option and movement columns as above, `SECMOVE_FIA_SEQ`, the fields of that `FIA` |

An unknown `level` is rejected when the query is bound; the error lists the valid values.

## Output columns

Every level starts with the same context columns:

| Column | Type | Description |
|---|---|---|
| `BLOCK1_HEADER` | `VARCHAR` | Basic header block `{1:...}` |
| `BLOCK2_HEADER` | `VARCHAR` | Application header block `{2:...}` |
| `FUNCTION` | `VARCHAR` | Function of the message, tag `23G` (`NEWM`, `REPL`, `CANC`, ...) |
| `ISIN` | `VARCHAR` | ISIN from the `USECU` `35B` field |
| `SECURITY_ALT_ID` | `VARCHAR` | Second line of `35B`, e.g. a local code |
| `SECURITY_DESC` | `VARCHAR` | Remaining lines of `35B`, joined with spaces |
| *qualifier columns* | detected | One column per qualifier (or `TAG_<tag>` for unqualified fields) found in `GENL`, `LINK`, `USECU`, `ACCTINFO`, `INTSEC`, `CADETL` and `ADDINFO` |

`INTSEC`, `CADETL` and `ADDINFO` are read as single sequences; if a message contains more than one, only the
first is used. The `35B` field of `INTSEC` and `SECMOVE` is returned unparsed as `TAG_35B`.

The level-specific columns follow, then `filename` and hive partition columns when requested.

### Column names and collisions

Columns are named after the SWIFT qualifier (`CAEV`, `RDTE`, `PAYD`, ...). When the same qualifier occurs in
two different sequences, the second one gets a numeric suffix. In the sample file, `PAYD` appears in
`CADETL`, in `CASHMOVE` and in `SECMOVE`, so the columns are `PAYD`, `PAYD_2` and `PAYD_3`. The suffixes
depend on the data, so check the schema with `DESCRIBE` before writing queries against a new feed:

```sql
DESCRIBE SELECT * FROM read_mt564('examples/notifications.txt', level = 'CASHMOVE');
```

### Unrecognised sequences

Fields of top-level sequences that the reader does not model (for example `CAOUTC`) are not dropped. At
`level = 'MESSAGE'` they are returned in `OTHER_FIELDS MAP(VARCHAR, VARCHAR)`, keyed as
`SEQUENCE.QUALIFIER`, in document order. Unknown sequences nested inside a modelled sequence are not
captured.

## Options

| Option | Type | Default | Description |
|---|---|---|---|
| `level` | `VARCHAR` | `'MESSAGE'` | Output grain: `MESSAGE`, `USECU_FIA`, `CAOPTN`, `CASHMOVE`, `SECMOVE` or `SECMOVE_FIA` |
| `nullstr` | `VARCHAR` or `VARCHAR[]` | none | Values to read as `NULL`, compared after trimming, e.g. `'UKWN'`. Ignored by type detection. Applies to qualifier columns only. |
| `empty_as_null` | `BOOLEAN` | `false` | Read empty `VARCHAR` values as `NULL`. Applies to qualifier columns only. |
| `auto_detect` | `BOOLEAN` | `true` | Detect qualifier column types from a sample. |
| `all_varchar` | `BOOLEAN` | `false` | Read all qualifier columns as `VARCHAR`. |
| `sample_size` | `BIGINT` | `2000` | Number of messages (not rows) sampled for column discovery and type detection. `0` or less samples all. |
| `filename` | `BOOLEAN` | `false` | Add a `filename` column. |
| `hive_partitioning` | `BOOLEAN` | `false` | Add a `VARCHAR` column for each `key=value` directory in the path. |
| `parallel` | `BOOLEAN` | `true` | Scan several files on several threads. `false` reads files one after another in input order. |

### MESSAGE

```sql
SELECT FUNCTION, ISIN, CAEV, CAMV, NUM_USECU_FIA, NUM_CAOPTN,
       NUM_CASHMOVE_TOTAL, NUM_SECMOVE_TOTAL, NUM_SECMOVE_FIA_TOTAL
FROM read_mt564('examples/notifications.txt');
```

| FUNCTION | ISIN | CAEV | CAMV | NUM_USECU_FIA | NUM_CAOPTN | NUM_CASHMOVE_TOTAL | NUM_SECMOVE_TOTAL | NUM_SECMOVE_FIA_TOTAL |
|---|---|---|---|---:|---:|---:|---:|---:|
| NEWM | XX0000000011 | DVCA | MAND | 2 | 1 | 1 | 0 | 0 |
| NEWM | XX0000000029 | DVOP | CHOS | 1 | 2 | 1 | 1 | 1 |
| NEWM | XX0000000037 | MRGR | CHOS | 1 | 2 | 1 | 1 | 1 |

Repeating sequences are summarised as counts. Their fields are available at the finer levels.

### CAOPTN

```sql
SELECT ISIN, CAEV, CAOPTN_SEQ, CAON, CAOP, DFLT, NUM_CASHMOVE, NUM_SECMOVE

```

| ISIN | CAEV | CAOPTN_SEQ | CAON | CAOP | DFLT | NUM_CASHMOVE | NUM_SECMOVE |
|---|---|---:|---:|---|---|---:|---:|
| XX0000000011 | DVCA | 1 | 1 | CASH | Y | 1 | 0 |
| XX0000000029 | DVOP | 1 | 1 | CASH | Y | 1 | 0 |
| XX0000000029 | DVOP | 2 | 2 | SECU | N | 0 | 1 |
| XX0000000037 | MRGR | 1 | 1 | CASE | Y | 1 | 1 |
| XX0000000037 | MRGR | 2 | 2 | NOAC | N | 0 | 0 |

`CAON` is zero-padded in the message (`001`) and detected as a number.

### CASHMOVE

```sql
SELECT ISIN, CAEV, CAOPTN_SEQ, CAOP, CASHMOVE_SEQ, CRDB, PAYD_2, GRSS, OFFR
FROM read_mt564('examples/notifications.txt', level = 'CASHMOVE');
```

| ISIN | CAEV | CAOPTN_SEQ | CAOP | CASHMOVE_SEQ | CRDB | PAYD_2 | GRSS | OFFR |
|---|---|---:|---|---:|---|---|---|---|
| XX0000000011 | DVCA | 1 | CASH | 1 | CRED | 2026-02-27 | USD0,54 | NULL |
| XX0000000029 | DVOP | 1 | CASH | 1 | CRED | NULL | GBP0,3125 | NULL |
| XX0000000037 | MRGR | 1 | CASE | 1 | CRED | 2026-04-20 | NULL | ACTU/EUR18,5 |

The payment date of the cash movement is `PAYD_2`, because `PAYD` is already used by the `CADETL` payment
date of message 2. Rates and prices are returned as written; see [Limitations](#limitations).

### SECMOVE

```sql
SELECT ISIN, CAEV, CAOPTN_SEQ, CAOP, SECMOVE_SEQ, CRDB_2,
       regexp_extract(TAG_35B, 'ISIN (\S+)', 1) AS DELIVERED_ISIN,
       coalesce(ADEX, NEWO) AS RATIO, NUM_SECMOVE_FIA
FROM read_mt564('examples/notifications.txt', level = 'SECMOVE');
```

| ISIN | CAEV | CAOPTN_SEQ | CAOP | SECMOVE_SEQ | CRDB_2 | DELIVERED_ISIN | RATIO | NUM_SECMOVE_FIA |
|---|---|---:|---|---:|---|---|---|---:|
| XX0000000029 | DVOP | 2 | SECU | 1 | CRED | XX0000000029 | 1,/42, | 1 |
| XX0000000037 | MRGR | 1 | CASE | 1 | CRED | XX0000000011 | 1,/10, | 1 |

- `CRDB_2` is the credit/debit indicator of the securities movement; `CRDB` belongs to the cash movement.
- The delivered security's `35B` field is not split into columns. `regexp_extract` returns its ISIN.
- In the merger, holders of `XX0000000037` receive `XX0000000011`.

### SECMOVE_FIA

```sql
SELECT ISIN, CAOPTN_SEQ, SECMOVE_SEQ, SECMOVE_FIA_SEQ, PLIS_2, DENO_2
FROM read_mt564('examples/notifications.txt', level = 'SECMOVE_FIA');
```

| ISIN | CAOPTN_SEQ | SECMOVE_SEQ | SECMOVE_FIA_SEQ | PLIS_2 | DENO_2 |
|---|---:|---:|---:|---|---|
| XX0000000029 | 2 | 1 | 1 | EXCH/XLON | GBP |
| XX0000000037 | 1 | 1 | 1 | EXCH/XNYS | USD |

`PLIS_2` and `DENO_2` describe the delivered security and can differ from `PLIS` and `DENO` of the notified
security, as in the merger (`EUR` received as `USD`).

## More examples

### Placeholder values as NULL

`:98B::RDTE//UKWN` marks an unknown record date. With `UKWN` declared as a NULL marker, `RDTE` is typed as
`DATE`:

```sql
SELECT ISIN, CAEV, RDTE, XDTE, EFFD
FROM read_mt564('examples/notifications.txt', nullstr = 'UKWN');
```

| ISIN | CAEV | RDTE | XDTE | EFFD |
|---|---|---|---|---|
| XX0000000011 | DVCA | 2026-02-13 | 2026-02-12 | NULL |
| XX0000000029 | DVOP | 2026-01-23 | 2026-01-22 | NULL |
| XX0000000037 | MRGR | NULL | NULL | 2026-04-15 |

Without `nullstr`, `RDTE` is `VARCHAR`.

### Splitting a rate into currency and amount

```sql
SELECT CORP, CAEV, CAOP,
       left(GRSS, 3)                                       AS currency,
       replace(substr(GRSS, 4), ',', '.')::DECIMAL(18,6)  AS gross_rate
FROM read_mt564('examples/notifications.txt', level = 'CASHMOVE')
WHERE GRSS IS NOT NULL;
```

| CORP | CAEV | CAOP | currency | gross_rate |
|---|---|---|---|---:|
| CA0000000001 | DVCA | CASH | USD | 0.540000 |
| CA0000000002 | DVOP | CASH | GBP | 0.312500 |

### Narrative text

```sql
SELECT ISIN, CAEV, ADTX
FROM read_mt564('examples/notifications.txt')
WHERE ADTX IS NOT NULL;
```

| ISIN | CAEV | ADTX |
|---|---|---|
| XX0000000029 | DVOP | SCRIP REFERENCE PRICE TO BE\nANNOUNCED ON 20260205 |

### Daily archive

```sql
SELECT filename, CAEV, count(*) AS notifications
FROM read_mt564('archive/2026/**/*.txt.gz', filename = true)
GROUP BY ALL
ORDER BY ALL;
```

## Limitations

- **Amounts and rates are not split.** SWIFT writes the currency and amount without a separator and uses a
  comma as decimal mark (`:92F::GRSS//USD0,54`). Such fields are returned as `VARCHAR` exactly as written.
- **Date and time fields are not typed as `TIMESTAMP`.** Only 8-digit `YYYYMMDD` values are detected as
  `DATE`. 14-digit values such as `PREP` (`20260114103000`) become `BIGINT`.
- **Placeholders keep date columns as text.** If any sampled value is not a date (for example `UKWN`), the
  column stays `VARCHAR`. Declare such values with `nullstr`.
- **Numeric-looking references may become numbers.** A reference such as `23.08659` can be detected as
  `DOUBLE`. Use `all_varchar = true`, or check `DESCRIBE`, where this matters.
- `nullstr` and `empty_as_null` do not apply to `FUNCTION`, `ISIN`, `SECURITY_ALT_ID` and `SECURITY_DESC`.
- A single file is always read by one thread. Split very large batches to use more cores.

## Multiple files

Qualifier columns are discovered across the sampled messages of all files. A qualifier present in one file
but not in another is `NULL` where it is missing.
